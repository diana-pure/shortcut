# Practice 10 — Deadlock и Race Condition

## Описание

Практика по типичным проблемам многопоточности: состояние гонки (race condition) и взаимная блокировка (deadlock).

## Проблема дедлока в переводах между кошельками

Наивная реализация перевода выглядит так:

```java
synchronized(from) {
    synchronized(to) {
        from.balance -= 1;
        to.balance   += 1;
    }
}
```

При 10 кошельках и кольцевых переводах (`wallet[i] → wallet[i+1]`) возникает **кольцевое ожидание**:

- Поток 0 захватывает `wallet[0]`, ждёт `wallet[1]`
- Поток 1 захватывает `wallet[1]`, ждёт `wallet[2]`
- ...
- Поток 9 захватывает `wallet[9]`, ждёт `wallet[0]`

Ни один поток не может продвинуться — все 10 заблокированы навсегда.

**Решение — упорядочивание блокировок:** всегда захватывайте замки в глобально фиксированном порядке (например, по `System.identityHashCode`). Кольцо ожидания становится невозможным.

## Тесты

| # | Тест | Описание |
|---|------|----------|
| 1 | `testRaceConditionFixed` | 10 потоков × 1000 инкрементов дают ровно 10 000 — без потерь при параллельном доступе |
| 2 | `testWalletsNoDeadlock` | 100 000 переводов между 10 кошельками завершаются за 10 с, суммарный баланс остаётся 1000 |
| 3 | `testLockOrderingPreventsDeadlock` | Два потока с одинаковым порядком `lock1 → lock2` не зависают |
| 4 | `testTryLockAvoidDeadlock` | `tryLock` с тайм-аутом: даже при встречном захвате хотя бы один поток завершает транзакцию |
| 5 | `testAtomicCAS` | `AtomicInteger.incrementAndGet()` корректен без `synchronized` — 1000 задач дают ровно 1000 |

## Что нужно реализовать

### SafeCounter

Потокобезопасный счётчик без потерь при конкурентном инкременте.

- `increment()` — атомарный инкремент (используйте `AtomicInteger` или `synchronized`)
- `get()` — возврат текущего значения

### WalletTransfer

Перевод баланса между двумя кошельками без дедлока.

- `transfer(Wallet from, Wallet to)` — уменьшает `from.balance` на 1, увеличивает `to.balance` на 1
- Порядок захвата замков должен быть детерминированным (не зависеть от порядка аргументов)
- Подсказка: сравните `System.identityHashCode(from)` и `System.identityHashCode(to)`, захватывайте тот, у которого хеш меньше, первым

### Wallet (предоставлен, изменять не нужно)

Простой контейнер баланса с публичным полем `balance`.

# Practice 12 — Тестирование конкурентных программ

## Задача

Реализовать потокобезопасный стек и пару производитель-потребитель с XOR-контрольной суммой.
Освоить стратегии тестирования конкурентного кода: safety, liveness и детерминированную проверку корректности.

## Тесты

| # | Тест | Описание |
|---|------|----------|
| 1 | `testSafeStackSafety` (×3) | 10 потоков одновременно делают push и pop — размер стека никогда не становится отрицательным. Тест повторяется 3 раза (`@RepeatedTest`), чтобы увеличить вероятность поймать гонку данных: однократный запуск может случайно пройти при неверной реализации |
| 2 | `testSafeStackLiveness` | 5 потоков выполняют по 100 push — все 500 вызовов завершаются без зависания за 5 секунд |
| 3 | `testSafeStackLifo` | Последовательный сценарий: push 1, 2, 3 → pop возвращает 3, 2, 1 (LIFO) |
| 4 | `testSafeStackEmptyException` | pop и peek на пустом стеке бросают `EmptyStackException` |
| 5 | `testChecksumIntegrity` | Производитель и потребитель запускаются одновременно через `CountDownLatch`; XOR всех отправленных и XOR всех принятых чисел должны совпасть |

## Классы

### SafeStack&lt;T&gt; — **реализовать**

Потокобезопасный стек на односвязном списке:
- Вложенный класс `Node<T>` с полями `value` и `next`.
- `ReentrantLock` защищает все мутирующие операции.
- Методы: `push`, `pop` (с `EmptyStackException`), `peek` (с `EmptyStackException`), `isEmpty`, `size`.

### ChecksumProducerConsumer — **реализовать**

Классическая схема производитель-потребитель с верификацией через XOR:
- Принимает `BlockingQueue<Integer>` и `CountDownLatch` для синхронного старта.
- `produce(int count)` — кладёт 1..count в очередь, вычисляет XOR, завершает sentinel-значением -1.
- `consume()` — читает очередь до -1, вычисляет XOR принятых чисел.
- Совпадение `producerChecksum` и `consumerChecksum` гарантирует, что каждое число передано ровно один раз.

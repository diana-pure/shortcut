# Инструкция по работе с практическими заданиями по Stream API

Данная инструкция предназначена для студентов, выполняющих практические задания 1–8 по теме **Stream API в Java**.

---

## 1. Подготовка окружения

Перед началом работы убедитесь, что у вас установлены:

- JDK 17 (или выше)
- IDE (IntelliJ IDEA / Eclipse / VS Code)

Maven устанавливать **не нужно** — каждое задание содержит встроенный **Maven Wrapper** (`mvnw`).

Проверка версии Java:

    java -version

### Maven Wrapper

Каждый проект содержит файлы:

    stream-task-N/
     ├── mvnw          ← скрипт для Linux/macOS
     ├── mvnw.cmd      ← скрипт для Windows
     └── .mvn/wrapper/ ← конфигурация враппера

Первый запуск автоматически скачает нужную версию Maven.

На macOS/Linux:

    ./mvnw test

На Windows:

    mvnw.cmd test

---

## 3. Структура проекта

Каждый проект имеет стандартную структуру:

    project-root/
     ├── pom.xml
     ├── README.md
     └── src
         ├── main
         │    └── java/com/example/streams/taskN/
         └── test
              └── java/com/example/streams/taskN/

### Важно:

- `README.md` — содержит текст задания с условием и ожидаемым поведением.
- `src/main/java` — здесь находятся классы с `TODO` — именно здесь работаете вы.
- `src/test/java` — тесты, проверяющие корректность реализации. **Не изменяйте тесты.**

---

## 4. Порядок выполнения задания

### Шаг 1. Прочитайте README

Внимательно изучите:

- цель задания
- условие и ограничения
- ожидаемое поведение методов

---

### Шаг 2. Найдите TODO

Откройте класс с незавершённой реализацией.

Пример:

    // TODO: реализовать метод через Stream API

Реализуйте метод без изменения его сигнатуры.

---

### Шаг 3. Запустите тесты

В корне проекта выполните:

    ./mvnw test

Если тесты падают — это нормально на старте.
Ваша цель — сделать так, чтобы сборка завершалась сообщением:

    BUILD SUCCESS

---

## 5. Правила выполнения

### Запрещено

- Изменять сигнатуры методов, имена классов и пакеты.
- Изменять тестовые классы.
- Использовать циклы `for`/`while` там, где задание требует Stream API.

### Разрешено

- Использовать любые методы из `java.util.stream.*`.
- Использовать вспомогательные приватные методы.
- Использовать `Collectors.*` и `Optional`.

## 7. Как понять, что решение корректное

Ваше решение считается корректным, если:

- проект компилируется
- все тесты проходят (BUILD SUCCESS)
- реализация использует Stream API, а не ручные циклы

## 8. Дополнительные вопросы для проверки понимания

После каждого задания попробуйте ответить:

1. Какие операции являются промежуточными, а какие — терминальными?
2. Почему стрим нельзя использовать дважды?
3. В чём разница между `map` и `flatMap`?
4. Когда стоит использовать `parallelStream`, а когда это опасно?

---

## 9. Общая цель практики

После выполнения всех заданий вы должны:

- уверенно читать и писать цепочки стримов
- понимать разницу между промежуточными и терминальными операциями
- знать, когда использовать `Optional`
- уметь группировать и агрегировать данные через `Collectors`
- понимать ограничения и риски параллельных потоков
